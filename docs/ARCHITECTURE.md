# 2.2 架构与安装事务

本体提供传感器采集、仪表盘、耗能日历、应用设置和插件/快捷键宿主。十四个可选功能以签名插件安装，四个共享适配包不直接暴露为用户功能。

- `App/`：本体、自包含 .NET 10、公共契约、共享桌面外壳及启动器。
- `Plugins/<id>/`：已选择的功能包或其依赖，含签名清单、所需程序集和固定第三方输入。
- `Shared/`：字节相同 DLL 的磁盘去重，由引用关系维护；不同 ABI/哈希保持隔离。
- 用户数据目录：历史、授权、偏好与缓存，独立于安装文件。

设备控制实际拆分程序集与后台注册：风扇、RGB 各有自己的后台；挂灯、路由器、显示器和采集播放不启动这两个后台。桌宠与网页适配分开，网页页签各有独立入口；连接设置和网页 SDK 按需共享。截图和效率使用同一个适配程序集，并保持各自原生运行时隔离。

## 契约与目录

插件 API 仍为 1；最低宿主版本由实际程序集版本判断。`PluginFeed` 描述分组、可选功能、共享依赖、大小、哈希和同次 Release 的附件。目录与包都用发布公钥验签，目录不是任意网址的代码执行入口。

`PluginInstallPlan` 从选择和已安装状态计算依赖闭包、下载、启停、卸载及旧整包替换；`ModuleChangeSet` 描述一次提交的多个操作。加载器只沿已验证的依赖图解析共享程序集，不扫描任意磁盘路径。

## 下载和事务

普通用户进程下载及缓存，所有包完成后才启动一次提权维护。维护器重新验证签名并解包暂存，校验组合依赖，退出托盘和相关子进程，停止后台后替换文件与状态，再等待后台就绪后提交。失败回滚整批；未提交的恢复日志在下次启动检查。

变更前的录制/导出保护继续有效。下载失败和取消不会提前停服务。旧六整包中的 devices、companion 自动映射到十个新子功能；先保留旧文件，完成新包事务后再移除，设置和数据路径沿用。display、applications、capture、efficiency 标识继续使用。

## 生命周期

副屏、风扇、RGB 等已启用后台由 Windows 服务承载。桌宠、截图、效率及自启工作台是托盘持有的子进程，退出按原保护流程清理。独立部署的机器人服务不被接管。未安装功能既不注册入口和快捷键，也不运行它的任务。
