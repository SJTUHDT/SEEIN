# 模块架构与构建边界

安装布局是 `App/` 本体及共享 .NET 8 运行库、`Plugins/<id>/` 可选实现、`Shared/` 按内容哈希复用的 DLL。相同字节的 DLL 可硬链接，ABI/版本不同的原生库保持隔离。逻辑文件大小和实际磁盘分配可能不同。

宿主为 WPF 桌面端与 Windows 服务。Contracts 定义插件 API 1 与消息；Modularity 负责包签名、完整性、加载及事务；Core 提供数据、传感器与宿主设施。模块通过页面工厂和服务入口注册，不能反向依赖 Tray/Service 外壳。

采样、消息发布、写库及副屏绘制独立调度，硬件共享一个采集器。各后台模块独立启动；桌面端在启动就绪后补发握手和当前页面读取。

桌宠、工具、显示器辅助程序由托盘持有；硬件辅助程序由后台持有；采集播放使用用户会话内的本地管线。外部已有机器人服务不因退出 SEEIN 被接管。

插件包包含 module.json、module.sig 和 SHA-256 文件清单，使用 RSA-PSS 验证来源，检查路径、体积、宿主版本和依赖。更改通过安全重启生效，不提供运行中卸载程序集。卸载保留用户数据。

开发者可构建自己的宿主、生成自己的发布密钥和公钥，再签名自己的插件；无需也不应取得官方私钥。自编译宿主的本地可信公钥必须与包匹配。第三方动态库的许可及替换权利保持不变，修改后的完整源构建方法见 BUILDING.md。
